# 결정 기록

현재 유효한 설계 결정만 남긴다. 번호는 코드 주석에서 참조하므로 바꾸지 않는다. 빠진 번호(D4, D23, D26)는 다른 결정으로 대체된 것이다.

## 구조·빌드

| # | 결정 |
| --- | --- |
| D1 | 최상위는 `src/` + `test/`. 서버는 `src/server`, 화면은 `src/resources/templates` |
| D3 | 마이그레이션은 `src/resources/migrations/*.sql` 순번 파일 |
| D9 | 빌드는 `tsc` + 리소스 복사. 번들러를 쓰지 않는다 |
| D27 | 런타임은 TypeScript(Node) 하나. 병목이 외부 I/O라 수집을 Go로 나눠도 이득이 없고, SQLite 동시 쓰기·로직 이중 구현·배포 2벌만 생긴다 |
| D30 | 서버는 기능별 패키지로 나누고, tier 의존 규칙을 `test/architecture.test.ts`로 강제한다. 위 tier의 동작은 콜백으로 연결한다 |
| D31 | 배포는 직접 설치(systemd)와 Docker Compose 두 가지. 컨테이너는 `ALLOW_NON_LOOPBACK_HOST`로 모든 인터페이스에 열고, 바깥 노출은 `127.0.0.1` 포트 매핑으로 막는다 |

## 수집·파싱

| # | 결정 |
| --- | --- |
| D10 | Status Page 입력은 Atom 규격을 기준으로 한다 |
| D11 | 장애 공지는 Atom `<id>` 전체로 식별한다(`source_id, atom_id`). `published`는 cutoff, `updated`는 참고용 |
| D12 | 프로필은 자동 감지하고, 모르는 공급자는 `generic`. 한 번 감지하면 저장하고 304에서는 다시 감지하지 않는다. 직접 지정이 우선 |
| D16 | 파싱은 2단계: Stage 1 형식 흡수, Stage 2 정규화. 둘 다 순수·결정적 |
| D18 | 인코딩 처리 분리: charset은 요청, 엔티티는 Stage 1, 태그는 Stage 2 |
| D19 | 프로필별 동작은 플래그 객체가 아니라 코드 모듈로 표현한다 |
| D20 | 요청은 연결(TLS·SSRF)과 요청(헤더) 두 계층. 403·핸드셰이크 실패는 TLS 1.2로 재시도하고 성공하면 `fetch_options`에 저장 |

## 발송

| # | 결정 |
| --- | --- |
| D2 | Discord 템플릿은 DB에 저장하고 실행 중에 편집한다 |
| D17 | 내장 프리셋 4종: `incident-active` · `news-article` · `link-discussion` · `minimal` |
| D22 | 메시지 옵션(조용히 보내기, 멘션, 포럼 스레드·태그, 기존 메시지 수정)은 소스가 가진다 |
| D24 | 그룹은 재사용하는 전송 채널이다. 웹훅 URL은 그룹만 가진다. 소스는 그룹이 하나 이상 필요하고, 목적지가 없으면 수집하지 않는다 |
| D25 | 발송 단위는 항목 × 연결 세대. 새 연결의 첫 수집은 보내지 않는 기준선, 결과 모르는 POST·PATCH 404는 관리자 검토, 대량 신규 보류, 공유 번역 캐시, 수집·발송 워커 분리 |

## 데이터·번역

| # | 결정 |
| --- | --- |
| D21 | Export/Import는 소스·그룹 설정 JSON 파일 하나. 웹훅 URL은 빼고, 들어온 소스는 신규 등록으로 취급해 과거 항목을 보내지 않는다 |
| D28 | 로그 4개를 `event_log` 하나로 합치고, 모델 설정은 환경 변수(`GEMINI_MODEL`)로, 항목의 발송·번역 사본은 없앤다. 메시지 수정은 유지한다 |
| D29 | 번역은 Gemini만 쓴다. `PRIMARY_MODEL_API_KEY` → `FALLBACK_MODEL_API_KEY` 순서로 같은 모델을 호출하고, 실패한 키는 5분 쉰다. 키별 한 번만 요청하고 모두 실패하면 원문을 보낸다. 키 원문은 DB·화면·로그에 남기지 않는다 |

새 결정은 마지막 번호 다음 번호로 해당 분류에 추가한다. 기존 결정을 대체하면 그 줄을 지우고 위 안내의 빠진 번호에 적는다.
